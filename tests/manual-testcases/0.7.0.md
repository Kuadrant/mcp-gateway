### Broker Prometheus metrics (phase 3)

**Related PR**: [#1293](https://github.com/Kuadrant/mcp-gateway/pull/1293)
**Why manual**: Metrics endpoint requires a running cluster. Verifying correct Prometheus output format, label values, and gauge zero-out on server failure cannot be covered by unit tests alone.

**Prerequisites**: Docker, `kubectl`, `kind`, `helm`, `curl` installed and on `$PATH`. Repo checked out at the `feature/metrics-phase3` branch.

#### Step 5: Verify gauge zeroes on server failure

Scale the upstream server to 0 replicas and wait for 3 consecutive health check failures (3× `--mcp-check-interval`, default 3 minutes — patch to `5s` for faster testing):

```bash
kubectl scale deployment everything-server -n mcp-test --replicas=0

# The broker's readiness probe returns 503 when no upstreams are healthy,
# so the pod will show 0/1 Running — this is expected, not a crash.
# Wait for the default health check interval (60s) for failures to accumulate,
# or patch the interval down first to speed things up:
kubectl set env deployment/mcp-gateway -n mcp-system MCP_CHECK_INTERVAL_SECS=5
# Wait ~20s for 3 consecutive failures (3 × 5s + backoff)
sleep 20

# Port-forward directly to the pod (deployment port-forward skips unready pods)
POD=$(kubectl get pod -n mcp-system -l app.kubernetes.io/name=mcp-gateway -o jsonpath='{.items[0].metadata.name}')
kubectl port-forward -n mcp-system pod/$POD 9090:9090 &
sleep 1
curl -s http://localhost:9090/metrics | grep -E "mcp_broker_(tools_discovered|tools_list_response_bytes|upstream_connection_failures|discovery_total)"
```

- [ ] `mcp_broker_tools_discovered{server_name="mcp-test/everything-server"}` drops to `0`
- [ ] `mcp_broker_tools_list_response_bytes{server_name="mcp-test/everything-server"}` drops to `0`
- [ ] `mcp_broker_upstream_connection_failures_total{server_name="mcp-test/everything-server"}` is `>= 1`
- [ ] `mcp_broker_discovery_total{server_name="mcp-test/everything-server",status="failure"}` is `>= 1`

#### Step 7: View metrics in Grafana

Deploy the OTel observability stack (Grafana, Tempo, Loki) and a minimal Prometheus that scrapes the broker:

```bash
# Deploy Grafana + Tempo + Loki
make otel
```

Wait for the observability pods to be ready:

```bash
kubectl wait --for=condition=Ready pod --all -n observability --timeout=120s
```

The broker metrics port is not on the Service (the controller owns and reconciles it).
Get the pod IP to scrape directly:

```bash
BROKER_POD_IP=$(kubectl get pod -n mcp-system -l app.kubernetes.io/name=mcp-gateway \
  -o jsonpath='{.items[0].status.podIP}')
echo "Broker pod IP: $BROKER_POD_IP"
```

Deploy a minimal Prometheus configured to scrape the broker pod IP directly:

```bash
kubectl apply -f - <<EOF
apiVersion: v1
kind: ConfigMap
metadata:
  name: prometheus-config
  namespace: observability
data:
  prometheus.yml: |
    global:
      scrape_interval: 15s
    scrape_configs:
    - job_name: mcp-gateway-broker
      static_configs:
      - targets: ['${BROKER_POD_IP}:9090']
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: prometheus
  namespace: observability
spec:
  selector:
    matchLabels:
      app: prometheus
  template:
    metadata:
      labels:
        app: prometheus
    spec:
      containers:
      - name: prometheus
        image: prom/prometheus:latest
        args: ['--config.file=/etc/prometheus/prometheus.yml']
        ports:
        - containerPort: 9090
        volumeMounts:
        - name: config
          mountPath: /etc/prometheus
      volumes:
      - name: config
        configMap:
          name: prometheus-config
---
apiVersion: v1
kind: Service
metadata:
  name: prometheus
  namespace: observability
spec:
  selector:
    app: prometheus
  ports:
  - port: 9090
    targetPort: 9090
EOF
```

Wait for Prometheus to be ready:

```bash
kubectl wait --for=condition=Ready pod -l app=prometheus -n observability --timeout=60s
```

Add Prometheus as a Grafana datasource:

```bash
kubectl patch configmap grafana-datasources -n observability --type=merge -p '
{
  "data": {
    "datasources.yaml": "apiVersion: 1\ndatasources:\n  - name: Tempo\n    type: tempo\n    access: proxy\n    url: http://tempo:3200\n    isDefault: true\n    jsonData:\n      httpMethod: GET\n      nodeGraph:\n        enabled: true\n  - name: Loki\n    type: loki\n    access: proxy\n    url: http://loki:3100\n    isDefault: false\n    jsonData:\n      derivedFields:\n        - name: TraceID\n          matcherRegex: \"\\\"traceid\\\":\\\"([^\\\"]+)\\\"\"\n          url: \"$${__value.raw}\"\n          datasourceUid: tempo\n          urlDisplayLabel: View Trace\n  - name: Prometheus\n    type: prometheus\n    access: proxy\n    url: http://prometheus:9090\n    isDefault: false\n"
  }
}'
# Restart Grafana to pick up the new datasource
kubectl rollout restart deployment/grafana -n observability
kubectl wait --for=condition=Ready pod -l app=grafana -n observability --timeout=60s
```

Kill any existing port-forwards, then forward Grafana:

```bash
pkill -f "port-forward" 2>/dev/null; sleep 1
kubectl port-forward -n observability svc/grafana 3000:3000 &
sleep 2
# verify it's up before opening the browser
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000
# Expected: 200
```

Open http://localhost:3000 in your browser (no login required — anonymous access is enabled).

- [ ] `mcp_broker_tools_discovered` query returns a result with `server_name="mcp-test/everything-server"`
- [ ] `mcp_broker_discovery_total` shows both `status="success"` and `status="failure"` series

### Router structured audit log for tool calls

**Related PR**: [#1347](https://github.com/Kuadrant/mcp-gateway/pull/1347) (CONNLINK-1385)
**Why manual**: Verifying structured log output requires a running cluster and live tool calls. Log content/format can't be asserted in e2e tests.

#### Prerequisites

Tools: `kind`, `kubectl`, `helm`, `curl`, `docker` or `podman` on `$PATH`.

#### Step 0: Stand up a fresh cluster with the local build

```bash
# From repo root, on the feat/audit-logging-connlink-1385 branch
make local-env-setup
```

`make local-env-setup` deploys using the published image. You must build and
push a local image to your own registry so the audit log code is actually
running. The deployment is owned by `MCPGatewayExtension` and the operator
reconciles it back to the released tag, so you need to scale the operator
down while testing.

```bash
# Build the local image (must be logged in: docker login quay.io)
make docker-build GATEWAY_IMG=quay.io/pstefans/mcp-gateway:audit-test
make docker-push GATEWAY_IMG=quay.io/pstefans/mcp-gateway:audit-test

# Scale the operator down so it doesn't reconcile the image back
kubectl scale deployment mcp-gateway-controller -n mcp-system --replicas=0

# Patch the deployment to use your build
kubectl set image deployment/mcp-gateway -n mcp-system \
  mcp-gateway=quay.io/pstefans/mcp-gateway:audit-test
kubectl rollout status deployment/mcp-gateway -n mcp-system --timeout=60s
```

Verify the correct image is running and upstreams are registered:

```bash
kubectl get pod -n mcp-system -l app.kubernetes.io/name=mcp-gateway \
  -o jsonpath='{.items[0].spec.containers[0].image}' && echo
# Expected: quay.io/pstefans/mcp-gateway:audit-test

kubectl get mcpserverregistration -A
# Expected: everything-server and stateless-server both READY=True
```

The gateway is exposed via NodePort — note the local port:

```bash
# HTTP gateway is on localhost:8001 (Kind port-mapping for NodePort 30080)
GW_URL=http://localhost:8001
GW_HOST=mcp.127-0-0-1.sslip.io
```

#### Step 1: Open a log tail in a separate terminal

```bash
kubectl logs -n mcp-system -l app.kubernetes.io/name=mcp-gateway -f \
  | grep '"tool call"'
```

Leave this running. The `grep` filters to audit entries only.

#### Step 2: Establish a session and make a tool call

The 2025-11-25 protocol requires an initialize/initialized handshake before
tool calls. Run these in sequence:

```bash
GW_URL=http://localhost:8001
GW_HOST=mcp.127-0-0-1.sslip.io

# 2a. Initialize — capture the gateway session ID
INIT=$(curl -si -X POST $GW_URL/mcp \
  -H "Host: $GW_HOST" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{
        "protocolVersion":"2025-03-26",
        "capabilities":{},
        "clientInfo":{"name":"manual-test","version":"1.0"}}}')
echo "$INIT" | grep "HTTP/"
# Expected: HTTP/1.1 200 OK

SESSION=$(echo "$INIT" | grep -i "mcp-session-id:" | awk '{print $2}' | tr -d '\r')
echo "SESSION=$SESSION"

# 2b. Send initialized notification
curl -s -X POST $GW_URL/mcp \
  -H "Host: $GW_HOST" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SESSION" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  -o /dev/null -w "%{http_code}\n"
# Expected: 202

# 2c. Call a tool
# Note: the `Accept: application/json, text/event-stream` header is required —
# the everything-server uses SSE for backend session init.
curl -s -X POST $GW_URL/mcp \
  -H "Host: $GW_HOST" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SESSION" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{
        "name":"everything_get-sum","arguments":{"a":7,"b":8}}}'
# Expected: HTTP 200, body contains "The sum of 7 and 8 is 15."
```

#### Step 3: Verify the audit log entry

In the log tail terminal you should see a line like:

```
time=... level=INFO msg="tool call" component=router user="" tool=get-sum server=mcp-test/everything-server status=200 request_id=... session=...
```

> **Note on `tool` field**: the router logs the upstream tool name after
> prefix stripping (`get-sum`, not `everything_get-sum`). This is the name
> the backend sees.

- [ ] `msg` is `"tool call"`
- [ ] `level` is `INFO`
- [ ] `tool` is non-empty (e.g. `get-sum`)
- [ ] `server` is `mcp-test/everything-server`
- [ ] `status` is `200`
- [ ] `request_id` is non-empty
- [ ] `session` is non-empty

#### Step 4: Verify user identity is captured (with auth)

Skip this step if running without an AuthPolicy. With OIDC or API key auth,
obtain a token and pass it as `Authorization: Bearer <token>`. The `user`
field in the audit log will contain the JWT `sub` claim.

- [ ] `user` field is non-empty and matches the token subject

#### Step 5: Verify tools/list produces no audit entry

```bash
curl -s -X POST $GW_URL/mcp \
  -H "Host: $GW_HOST" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: $SESSION" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/list"}' \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(len(d['result']['tools']), 'tools')"
# Expected: 16 tools (or similar)
```

Check the log tail — no new `"tool call"` line should appear.

- [ ] Only the entries from Step 2 are present in the log tail

