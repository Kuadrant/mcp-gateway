# Manual Test Cases — 1.1.0

## Observability

### Broker metrics scraped through a `port: metrics` PodMonitor

**Related PR**: Fix for [#1572](https://github.com/Kuadrant/mcp-gateway/issues/1572).

**Why manual**: The e2e CI environment does not run Prometheus Operator. This
scenario checks that Prometheus discovers the broker container's named `metrics`
port and scrapes it. The port declaration itself is covered by unit tests.

- [ ] Set up the local environment from the branch being tested and confirm the
  broker container declares `metrics` on port `9090`:
  ```bash
  make local-env-setup
  kubectl get deploy mcp-gateway -n mcp-system -o json |
    jq -e '.spec.template.spec.containers[0].ports[] | select(.name == "metrics" and .containerPort == 9090 and .protocol == "TCP")'
  ```

- [ ] Install Prometheus Operator:
  ```bash
  kubectl apply --server-side --force-conflicts \
    -f https://github.com/prometheus-operator/prometheus-operator/releases/download/v0.94.1/bundle.yaml
  kubectl wait --for=condition=Available deployment/prometheus-operator -n default --timeout=180s
  ```

- [ ] Create a `Prometheus` that selects `PodMonitor`s in `mcp-system`:
  ```bash
  kubectl apply -f - <<EOF
  apiVersion: v1
  kind: ServiceAccount
  metadata:
    name: prometheus
    namespace: mcp-system
  ---
  apiVersion: rbac.authorization.k8s.io/v1
  kind: Role
  metadata:
    name: prometheus
    namespace: mcp-system
  rules:
    - apiGroups: [""]
      resources: ["pods"]
      verbs: ["get", "list", "watch"]
  ---
  apiVersion: rbac.authorization.k8s.io/v1
  kind: RoleBinding
  metadata:
    name: prometheus
    namespace: mcp-system
  roleRef:
    apiGroup: rbac.authorization.k8s.io
    kind: Role
    name: prometheus
  subjects:
    - kind: ServiceAccount
      name: prometheus
      namespace: mcp-system
  ---
  apiVersion: monitoring.coreos.com/v1
  kind: Prometheus
  metadata:
    name: prometheus
    namespace: mcp-system
  spec:
    serviceAccountName: prometheus
    podMonitorSelector: {}
  EOF
  kubectl wait --for=condition=Available prometheus/prometheus -n mcp-system --timeout=180s
  ```

- [ ] Apply the `PodMonitor` from the "Scraping the metrics endpoint" section of
  `docs/guides/opentelemetry.md`:
  ```bash
  kubectl apply -f - <<EOF
  apiVersion: monitoring.coreos.com/v1
  kind: PodMonitor
  metadata:
    name: mcp-broker
    namespace: mcp-system
  spec:
    selector:
      matchLabels:
        app.kubernetes.io/name: mcp-gateway
    podMetricsEndpoints:
      - port: metrics
        path: /metrics
  EOF
  ```

- [ ] Port-forward Prometheus:
  ```bash
  kubectl port-forward -n mcp-system svc/prometheus-operated 9091:9090 &
  PF_PID=$!
  ```

- [ ] Confirm there is one healthy target per broker pod, scraped at
  `<pod-IP>:9090/metrics` with `endpoint="metrics"`. The target can take up to
  a minute to appear. Repeat the command until it succeeds:
  ```bash
  POD_IPS=$(kubectl get pod -n mcp-system -l app.kubernetes.io/name=mcp-gateway -o json |
    jq -c '[.items[].status.podIP] | sort')
  curl -s 'http://localhost:9091/api/v1/targets?state=active' |
    jq -e --argjson ips "$POD_IPS" '
      [.data.activeTargets[] | select(.scrapePool == "podMonitor/mcp-system/mcp-broker/0")] |
      ($ips | length) > 0 and
      length == ($ips | length) and
      all(.[]; .health == "up" and .labels.endpoint == "metrics") and
      ([.[].scrapeUrl] | sort) == ($ips | map("http://\(.):9090/metrics"))'
  ```

- [ ] Confirm `up` is `1` for every broker pod. Prometheus Operator sets `job` to
  `<namespace>/<PodMonitor name>`, so the query only matches the `mcp-broker`
  targets:
  ```bash
  curl -s 'http://localhost:9091/api/v1/query' \
    --data-urlencode 'query=up{job="mcp-system/mcp-broker",endpoint="metrics"}' |
    jq -e --argjson ips "$POD_IPS" '.data.result | ($ips | length) > 0 and length == ($ips | length) and all(.[]; .value[1] == "1")'
  ```

- [ ] Clean up. The monitoring CRDs are left installed because other local
  targets, such as `make otel`, also use them:
  ```bash
  kill $PF_PID
  kubectl delete podmonitor mcp-broker -n mcp-system
  kubectl delete prometheus prometheus -n mcp-system
  kubectl delete rolebinding,role,serviceaccount prometheus -n mcp-system
  kubectl delete deployment,service,serviceaccount prometheus-operator -n default
  kubectl delete clusterrolebinding,clusterrole prometheus-operator
  ```

## Controller

### Controller memory with unrelated cluster objects

Envtest covers cache membership. Run this check on a real cluster to measure
heap and container restarts under load.

Use a disposable kind or ROSA cluster with the controller build under test and
one standalone controller replica. Have at least one MCPGatewayExtension,
MCPServerRegistration, and MCPVirtualServer so each reconciler has work on
startup. Leave local port 18082 free.

Run the steps in one Bash shell from the repository root. Put the Bash fixture
script from CONNLINK-2025 at `./load-test.sh` and the disposable cluster's
kubeconfig at `./kubeconfig`. The script always uses that kubeconfig.

- [ ] Check the context, confirm the fixture namespaces are absent, and record
  an idle baseline. Pass when all six counts are zero, the controller pod is
  Ready with zero restarts and no `OOMKilled` reason, and the baseline contains
  15 heap samples.

  ```bash
  set -euo pipefail
  export KUBECONFIG="$PWD/kubeconfig"
  kubectl config current-context
  ns=mcp-system
  controller=mcp-gateway-controller
  results=$(mktemp -d)
  printf 'Results directory %s\n' "$results"
  metrics=http://127.0.0.1:18082/metrics
  metrics_pid=
  trap 'if [[ -n "$metrics_pid" ]]; then kill "$metrics_pid" 2>/dev/null || true; fi' EXIT

  fixture_counts() {
    local expected=$1 resource namespace batch count
    while read -r resource namespace batch; do
      count=$(kubectl -n "$namespace" get "$resource" -l "app=load-test,batch=$batch" -o name |
        awk 'END { print NR }')
      printf '%-18s %s\n' "$resource" "$count"
      [[ "$count" == "$expected" ]] || return 1
    done <<'EOF'
  namespaces default namespace-load
  deployments deployment-load-test deployment-load
  services service-load-test service-load
  serviceaccounts sa-load-test sa-load
  configmaps configmap-load-test configmap-load
  networkpolicies netpol-load-test netpol-load
  EOF
  }

  selector=$(kubectl -n "$ns" get deployment "$controller" -o json |
    jq -er '.spec.selector.matchLabels | to_entries |
      map("\(.key)=\(.value)") | join(",") | select(length > 0)')

  controller_pod() {
    kubectl -n "$ns" get pods -l "$selector" -o json |
      jq -er '[.items[] | select(.metadata.deletionTimestamp == null)] |
        select(length == 1) | .[0].metadata.name'
  }

  check_controller() {
    kubectl -n "$ns" get pod "$pod" -o json |
      jq -e '.metadata.deletionTimestamp == null and
        any(.status.conditions[]?; .type == "Ready" and .status == "True") and
        any(.status.containerStatuses[]?; .name == "mcp-controller" and
          .restartCount == 0 and .state.terminated.reason != "OOMKilled" and
          .lastState.terminated.reason != "OOMKilled")'
  }

  start_metrics() {
    kubectl -n "$ns" port-forward "pod/$pod" 18082:8082 > "$results/port-forward.log" 2>&1 &
    metrics_pid=$!
    curl -fs --retry 10 --retry-delay 1 --retry-connrefused --max-time 5 -o /dev/null "$metrics" ||
      { cat "$results/port-forward.log"; return 1; }
  }

  heap_bytes() {
    curl -fsS --max-time 5 "$metrics" |
      awk '$1 == "go_memstats_heap_inuse_bytes" && $2 > 0 {
        printf "%.0f\n", $2
        found = 1
      } END { exit !found }'
  }

  sample_heap() {
    local i
    for ((i = 0; i < 15; i++)); do
      heap_bytes || return 1
      sleep 2
    done
  }

  heap_peak() {
    awk 'NR == 1 || $1 > peak { peak = $1 }
      END { if (!NR) exit 1; print peak }' "$1"
  }

  absent=$(kubectl get namespaces deployment-load-test service-load-test sa-load-test \
    configmap-load-test netpol-load-test --ignore-not-found -o name)
  [[ -z "$absent" ]]
  fixture_counts 0
  kubectl -n "$ns" rollout status "deployment/$controller" --timeout=3m
  pod=$(controller_pod)
  check_controller
  start_metrics
  sample_heap > "$results/baseline.heap"
  check_controller
  baseline_peak=$(heap_peak "$results/baseline.heap")
  printf 'Baseline peak heap %s bytes\n' "$baseline_peak"
  limit=$(( baseline_peak + 10 * 1024 * 1024 ))
  ```

- [ ] Run the fixture script once and sample the same pod during creation and
  for 30 seconds afterward. Pass when the namespace-scoped counts are 200 for
  each of the six kinds, the original pod is still Ready with zero restarts
  and no `OOMKilled` reason, and peak heap is at most 10 MiB above the baseline
  peak. Use the counts below because the fixture script uses the context's
  current namespace for its namespaced counts.

  ```bash
  (
    if ! base64 -w 0 </dev/null >/dev/null 2>&1; then
      # The fixture script uses GNU base64's no-wrap option.
      base64() { command base64 | tr -d '\n'; }
      export -f base64
    fi
    bash ./load-test.sh
  ) > "$results/fixtures.log" 2>&1 &
  load_pid=$!
  while kill -0 "$load_pid" 2>/dev/null; do
    if ! heap_bytes >> "$results/load.heap"; then
      wait "$load_pid"
      exit 1
    fi
    sleep 2
  done
  wait "$load_pid"
  fixture_counts 200
  sample_heap >> "$results/load.heap"
  check_controller
  load_peak=$(heap_peak "$results/load.heap")
  printf 'Peak heap under load %s bytes (limit %s)\n' "$load_peak" "$limit"
  (( load_peak <= limit ))
  ```

- [ ] Restart the controller with the fixtures still present. Pass when a new
  pod is Ready with zero restarts and no `OOMKilled` reason, all three
  reconciler counters are positive, and peak heap is at most 10 MiB above the
  baseline peak.

  ```bash
  kill "$metrics_pid"
  wait "$metrics_pid" 2>/dev/null || true
  metrics_pid=
  old_pod=$pod
  kubectl -n "$ns" rollout restart "deployment/$controller"
  kubectl -n "$ns" rollout status "deployment/$controller" --timeout=3m
  pod=$(controller_pod)
  [[ "$pod" != "$old_pod" ]]
  check_controller
  start_metrics
  sample_heap > "$results/restart.heap"
  check_controller
  curl -fsS --max-time 5 "$metrics" > "$results/restart.metrics"
  for name in mcpgatewayextension mcpserverregistration mcpvirtualserver; do
    awk -v name="$name" '/^controller_runtime_reconcile_total[{]/ &&
      index($0, "controller=\"" name "\"") && $NF > 0 { print; found = 1 }
      END { exit !found }' "$results/restart.metrics"
  done
  restart_peak=$(heap_peak "$results/restart.heap")
  printf 'Peak heap after restart %s bytes (limit %s)\n' "$restart_peak" "$limit"
  (( restart_peak <= limit ))
  ```

- [ ] Clean up even if an earlier check failed. Pass when the namespace query
  finds no load namespaces and none of the five dedicated fixture namespaces.
  Exit the Bash shell to stop the metrics port-forward.

  ```bash
  set -e
  export KUBECONFIG="$PWD/kubeconfig"
  fixture_namespaces=(deployment-load-test service-load-test sa-load-test
    configmap-load-test netpol-load-test)
  kubectl delete namespaces -l app=load-test,batch=namespace-load --timeout=5m
  kubectl delete namespaces "${fixture_namespaces[@]}" --ignore-not-found --timeout=5m
  remaining=$(kubectl get namespaces -l app=load-test,batch=namespace-load -o name &&
    kubectl get namespaces "${fixture_namespaces[@]}" --ignore-not-found -o name)
  [[ -z "$remaining" ]]
  printf 'No fixture namespaces remain\n'
  ```
